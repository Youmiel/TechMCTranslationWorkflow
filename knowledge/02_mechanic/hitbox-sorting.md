# Hitbox Sorting（碰撞箱分选）

## 要点

- **机制定义**：在一条水道中，利用**不同大小的方块碰撞箱**把输出物品按目标分选到不同位置；物品实体的碰撞箱本身都一样大，靠的是挡路的方块碰撞箱尺寸差异（类似路上不同车道）。
- **工作方式**：物品沿水道被水流推送，依次撞上不同尺寸的碰撞箱——撞不上（尺寸小于间隙）的继续前进，撞上（尺寸大于等于间隙）的留在当前位置，从而归入不同槽位/等级。
- **典型应用**（QSDpdXT9SPs）：烟花火箭按等级（时长一/二/三级）分选——各等级火箭只走一条水道，通过碰撞箱逐级拦截归入正确等级，**只过一条水道而非每条等级一条水道**（c119-124）。
- **设计定位**：碰撞箱分选属于**存储系统的高阶布线方式**——平凡的布线思路是"不同产物各走各的水道"，碰撞箱分选用一条水道承载多种产物，靠碰撞箱在途中分流，属于布线上的优化技巧。
- 与「服务端碰撞箱（server-sided hitbox）」是不同概念：前者是**利用碰撞箱做分选**，后者指碰撞箱的**服务端/客户端归属**。

## 翻译注意事项

- 语境译名：碰撞箱分选 / 水道碰撞箱分选（2026-08-23 用户确认）。
- 分选中"撞上下一个尺寸更大的碰撞箱"（collide with the next size up hit box）译时保留"尺寸递增"逻辑，勿省略。
- 易混：hitbox（碰撞箱）≠ bounding box（边界箱/包围盒），本机制语境用碰撞箱。
