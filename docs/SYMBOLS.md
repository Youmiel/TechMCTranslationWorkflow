# 符号使用约定（SYMBOLS）

> 本项目文档、任务文件、脚本注释与产物中**符号的分工**。目标：一个符号只干一件事，
> 且**按“谁解析”分层**——机器解析的符号不得与人类阅读的符号混用。

## 符号分工

| 符号 | 用途 | 判据 | 解析方 |
|------|------|------|--------|
| `` ` `` | 代码 / 路径 / 文件名 / 命令 / 字段名 / 正则 / 参数 | 可直接复制执行或定位文件 | 人 + 脚本 |
| `【】` | **产物标记** | 仅登记在下表的 3 个，**新增必须先加脚本 regex** | 脚本（枚举匹配） |
| `[]` | **状态标记**（产物内）+ **文档标注** | `[待审核]` 类状态；`[推荐]` 类标注 | 脚本（部分）+ 人 |
| `<>` | **占位符** | 需替换为具体值的位置 | 人 |
| `「」` | **引用具名对象** + **译文内对话引号** | ① 引号内容 == 某文档标题全文 / 分节名（`四、内容边界`）/ 真实文件名<br>② 字幕译文内的对话引号 | 人 |
| `“”` | **指称概念 / 说法** | 行文中提及某个词、说法、做法、口径（不指向具名对象） | 人 |
| `（）` | 括注补充说明 | 非语义性补充，可删不影响句意 | 人 |
| `《》` | 书名 / 报刊名 | 自然语言用法 | 人 |

> ⚠️ **`「」` 与 `“”` 的区别不是“中文引号 vs 英文引号”**——两者都是中文引号。本项目
> 借用 `「」` 专门承载“引用具名对象”与“译文对话”，`“”` 承载普通指称。
> 这属**项目内约定**（国标 GB/T 15834 中二者同级），有辨识价值，但偏离通用规范。

## `【】` 产物标记登记表

| 标记 | 归属 | 消费方 | 性质 |
|------|------|--------|------|
| `【承接句】` | reflow / reflow2 补标点块 | `STITCH_RE`、`STITCH_PREFIX_RE`、`STITCH_RESIDUAL_RE`、`CROSS_MARKS` | 进产物文件 |
| `【延伸句】` | 同上 | 同上 | 进产物文件 |
| `【强制断句】` | 断句点清单 → 补标点先验知识 | 由 `srt_reflow_breaks.py` 派生 | **非产物文本**，Agent 不手写 |

**唯一例外（非工作流产物）**：`video-abstract` 的 `【注意】`/`【译注】`/`【搬运注】` 是该
skill 自己产出的发布摘要内标记，属其产物标记，不受本表登记约束。

## `[]` 状态标记

`[待审核]` / `[推断]` / `[ASR 推测]` / `[ASR]` / `[放行]` / `[通用词]` / `[待查]` / `[ID 待补]` / `[标记]`（格式占位）。

> `[ASR]` / `[放行]` 是 `.asr.tsv` 的**触发清单决策**口径（前者按清单给的正确词形修正，后者判定不必改）：
> `asr_check_trigger.py` 按这两个字面量判“清单项是否已消化”，**改字面量必须同步该脚本的 `DECIDED`**。

统一写**方括号**，不写 `【】`——`plan.py` 的 `PLACEHOLDER_RESIDUAL_RE` 按 `[...]` 匹配。

## 译文引号

字幕译文（`ref_translations/` 样本、`s04_draft.srt` / `r04_*.srt` 产物）中**对话引号一律用 `「」`**
（排版美观、中文习惯）。规则落点：

- `segment-subtitles`（断句规范，译文标点口径）
- `translate-redstone/task-translate.md` 与 `reflow-redstone/task-translate.md`（翻译任务规则）

## 标题写作

**标题只用稳定名词，括注一律不用**——这不是风格偏好，是**可校验契约**（`check_phase_sync.py` E 组）。

| 场景 | 错误 | 正确 |
|------|------|------|
| 解释性补充 | `### 输出纪律（核心，不可破）` | `### 输出纪律` + 正文首行 `> 核心，不可破` |
| 参数清单 | `### 输出（写入 _work/…/chunk_<k>.txt）` | `### 输出`（正文已给路径） |
| 限定词 | `### 四级查找（位置与执行）` | `### 四级查找` 或 `### 四级查找：位置与执行` |
| 语义组成 | `### proper_nouns（人物/组织）` | `### proper_nouns 人物组织` 或移正文 |

**为什么禁**：Markdown 锚点 = 标题文本逐字匹配，带括注导致两个真实故障——

1. **静默断链**：引用方写短形式（`#四级查找`）匹配不上实际锚点（`#四级查找位置与执行`）
2. **引号分类误判**：分类器按“标题全文相等”判定，短形式匹配失败 → 被误判为“指称概念”→ 错改成 `“”`

**E 组判据 = 标题内任意位置的全角括注**（不限末尾）——`### X（a）：说明` 这种中间括注同样污染锚点。

## 标题不写死数量词

**标题只用稳定名词，不写可变的数量词**（`四级查找` / `三档决策` / `三种词汇表…`）——数量是**内容**、会变；写进标题就要求内容永不变，否则标题与内容失同步，进而触发大量引用更改。

| 场景 | 错误 | 正确 |
|------|------|------|
| 源的层数会变 | `## 四级查找` | `## 术语源优先级` |
| 档位会增删 | `### 三档决策` | `### 修复档位决策` |
| 词汇表套数会变 | `## 三种词汇表的表头差异` | `## 词汇表表头差异` |

**判据（可机械校验）**：标题含 `[一二三四五六七八九十0-9]+\s*(级\|档\|种\|条\|步\|层\|类)` 即违规。

**为什么必须禁**：数量是**数据**（表格列值，可增删），标题不该跟着动；写死数量会迫使后续为“不改标题”而**硬塞**——`L1.5` 就是“为不改标题而降级塞入”的产物。

## `>` 引用块

**正当用途仅 3 种**：

1. `> ⚠️ …` 警示块——需脱离正文的视觉阻断
2. 外部内容引用——原文摘录 + 出处
3. 文档导语——`#` 标题后一次，须完整句

**禁止**：

- 标题后紧跟**短语型** `>`（限定词 / 强调语）
- 正文中用 `>` 承载可直接写成正文的强调段

**判据（客观、零硬编码）**：**完整句必有句末标点，短语必无**。

**三条出路（按短语性质选）**：

| 短语性质 | 出路 |
|----------|------|
| 在说“本节很重要/不可破” | **删**（结构已表达；且属元表述，见 `skill-writing-principles`） |
| 在界定本节 scope / 判据 | **并回标题**（冒号连接） |
| 是本节首条规则的浓缩 | **扩成正文首句**（完整句） |

## 写作示例

| 场景 | 正确 | 说明 |
|------|------|------|
| 指称某个说法 | `此时不要“顺手”改别处` | 概念 → `“”` |
| 指称某个口径 | `执行“只看点”的分类法` | 概念 → `“”` |
| 引用节名 | `见 [subagent-dispatch#派发边界](…)` | **优先用 Markdown 链接**，比 `「」` 更可校验 |
| 引用节名（无链接） | `见 conventions「长视频分块」` | 引用具名对象 → `「」` |
| 引用文件名 | `「S19+20」是合句标题格式` | 具名对象 → `「」` |
| 占位符 | `<工作目录>` / `<视频 ID>` | 统一 `<>` |
| 状态标记 | `[待审核] 候选：亚刻` | 方括号 |
| CLI 帮助标注 | `[推荐] 生效空隙点 tsv` | 方括号（非产物） |
| 译文对话 | `他说：「这样就行了。」` | 译文 → `「」` |

## 已知豁免区：`knowledge/` 与 `indexes/`

`knowledge/**`（术语表 CSV `notes` 列 + 机制知识卡）与 `indexes/**` 的 `「」` 主要为**引用
zh wiki 页面名**（`来源：zh wiki「凋灵笼（教程）」页`）与**术语指称**（`「合成网格」`）。

`knowledge/` 是**人工维护的核心资产**（AGENTS.md 核心原则 #4：物理隔离、可人工审核），
批量脚本改写会污染内容；且 wiki 页面名属具名对象（引用语义成立）。故：

- 新增条目：引用 wiki 页面名 → `「」`；指称术语/说法 → `“”`
- 存量按新规则**逐步收敛**，不做机械替换

**校验范围提示**：`scripts/check_phase_sync.py` 的扫描范围不含 `knowledge/`、`indexes/`。

## `「」` 弱引用

`「」` 引用**具名对象**时是弱引用（无锚点机制，Markdown 不报错）——故需**格式约定**才能校验。

**写法**：

| 场景 | 格式 | 例 |
|------|------|-----|
| 外部引用 | `「<skill 名\|文件名\|目录名>#<标题>」` | `「subagent-dispatch#派发配方」` |
| `SKILL.md` | 用 **skill 名**（非 `SKILL.md`，否则 18 个文件歧义） | `「redstone-conventions#断点恢复」` |
| 重名文件 | 带目录（`task-fix.md` / `README.md` 等 4 组重名） | `「reflow-redstone/task-fix.md#输出」` |
| 同文件引用 | **无 `#`**，直接写标题 | `「断点恢复」` |
| 分节名 | 同文件引用（`_discipline.md` 式） | `「四、内容边界」` |

**校验判据（F 组，警告级）**：无 `#` → 按同文件引用查本文件标题；找不到即报。

**豁免（形态判据）**：

- 代码围栏内 / 反引号内——格式骨架与符号说明**示例**（是在示范，不是在引用）
- 分节名（`N、<节名>`）、译文对话（引号内以句末标点收尾）
- `.py` 文件**不产出标题**，故其中 `「」` 一律须带文件名

> ⚠️ **F 组只能验“存在性 / 归属”，不能验“指向正确”**——未命中可能是指称概念、仓库外对象
> 或有意的短形式，故为**警告级**（`check_phase_sync.py` 的 `WARN_GROUPS`，不拦退出码），
> 需借上下文裁定。
